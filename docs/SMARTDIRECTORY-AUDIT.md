SmartDirectoryAI + HighLevel Platform: Complete Documentation
I explored every major section of your Legal Search Hub dashboard. Here's how the whole system fits together, and what it means for your Next.js integration.
Overall architecture
SmartDirectoryAI is a custom app embedded into your HighLevel (GoHighLevel) sub-account as an iframe, reachable via the "SmartDirectoryAI" item in the left sidebar. It sits on top of native HighLevel primitives (Contacts, Workflows, Forms, Custom Values) rather than replacing them, so the directory's data and events flow directly into standard HighLevel objects you already have access to. The public-facing directory website is white-labeled to your own domain (legalsearchhub.com, configured under Branding > Domain), and its navigation, URL slugs, and page copy are all editable through the app rather than through code.
Dashboard and analytics
The SmartDirectoryAI dashboard shows traffic, listings counts (free/claimed/premium), revenue, engagement (reviews, newsfeed, blogs, jobs, events), a growth chart, "Marketplace Health" (new/free/premium listings per month), and a "Directory Health Score" blending listings volume, claim rate, premium conversion, visibility, and activity into a single 0–100 score with a letter-grade-like label ("Poor" in your current test data). This is purely a reporting layer; there's no indication it exposes a public API of its own.
Listing management (Businesses tab)
Businesses are organized into "All Accounts," "Premium Accounts," "Free Accounts," and "Listing labels" (categories, currently 40 for this demo, with bulk CSV upload support — directly useful for seeding your legal practice-area taxonomy). Each individual listing has seven sub-sections: Analytics (pending/claim/approved requests, followers, reviews), Account Owner (assigns a "Consumer" record as the claiming owner), Business Details (profile/cover images, category labels, a custom URL slug, name, website, full address fields, phone, and a rich-text description — this is the core listing data model you'd need to replicate or sync into Next.js), Blogs, Events, Jobs, and News Feed (each a simple mini-CMS scoped to that one business, letting a claimed listing post its own content). "Consumers" (a separate top-level tab) are the end-user accounts that claim listings, follow businesses, and leave reviews — distinct from the businesses themselves.
Pricing and tier configuration (Plans tab)
There are two plans by default: "Community Listing" (free, $0) and "Local Spotlight" ($29/month or $299/year). Each plan has a granular feature matrix — around two dozen toggleable fields (address, phone, website, images, description, business hours, additional images, extra links, blogs, events, jobs, news feeds, teams, site reviews, etc.) with independent "Included" (shows a checkmark/X on a pricing table) and "Show" (hides the row entirely) switches. Plans also support an "External checkout" toggle that lets you redirect monthly/annual signups to an outside checkout URL (e.g., your own Stripe Checkout or a custom Next.js billing flow) instead of using HighLevel's native billing, plus a configurable trial period, add-ons, an "Upgrade Page" with custom header text, and a coupon system (none created yet). This external-checkout option is probably your cleanest integration point if you want billing to live in your own Next.js app rather than inside HighLevel.
Integrations (Settings > Integrations)
This is the most directly relevant tab for you. It shows Stripe Integration (connected, account "Legal Search Hub" — this is what powers native checkout when External Checkout is off), fields for a Google Maps API key (both a website-restricted and an IP-restricted key, currently empty, needed for map displays and listing geocoding), a reCAPTCHA protection toggle, a Google Analytics Measurement ID field, and — most importantly for you — an "AI Conversations API Key" section with a "Generate API Key" button. I did not generate a key since that would change account settings, but this strongly suggests SmartDirectoryAI exposes a REST API (likely for reading/writing conversation or chat data) that a headless frontend could call directly. If you want to pursue a decoupled Next.js frontend, this API key is probably your entry point, and I'd recommend asking the vendor/support for API documentation before generating it.
Workflow Mapping — the automation backbone (Settings > Workflow Mapping)
This is where the directory app and HighLevel automation actually connect. There are about twelve directory-side events — Claim Request Approved, Claim Request Rejected, Forgotten Password, Listing Upgraded To Premium, New Business Request, New Event Added, New Listing Added, New User Created, Reset Password, User Applied for Job, New Blog Added, New Claim Request, and News Feed Created — and each one is mapped, by matching name, to a same-named Workflow inside HighLevel's Automation section. I confirmed in the actual Workflow builder that these live under Automation > Workflows > "SmartDirectoryAI Workflows" > "System Workflows," each pre-built as Trigger → Action(s) → End. The one I opened ("New Blog Added") has a pre-written notification email using HighLevel merge fields ({{location.name}}, {{location.email}}) but, notably, its trigger slot was empty ("Add new trigger") — meaning these ship as templates that need a trigger wired up, most plausibly HighLevel's "Inbound Webhook" trigger type (which I found by searching the trigger picker, under Triggers > Events > Inbound Webhook). That points to the real mechanism: SmartDirectoryAI's backend almost certainly POSTs to a per-workflow inbound webhook URL whenever one of those twelve events fires, and you customize what happens next (send email, update a contact, notify Slack, etc.) using the full HighLevel workflow builder. There's a separate "Outreach Workflows" folder containing sales/nurture campaigns (Free Listing Outreach, Free Listing Outreach – Customer Replied, Marketing Services Push, Premium Upgrade Push, SAAS Push) that appear to run the upsell funnel for converting free listings into paying customers.
Forms and embeds
Under Branding > Content, the homepage "Optin" section lets you pick any HighLevel form from your sub-account to embed. Under Sites > Forms there's currently one form ("Contact") built with HighLevel's native drag-and-drop form builder. HighLevel forms can be embedded via iframe or JS snippet in any external site, so this is a straightforward way to reuse your existing lead-capture forms inside a custom Next.js site without rebuilding them.
Custom Names / URL routing (Settings > Custom Names)
This tab lets you rename navigation labels and, importantly, shows the underlying route slugs the directory uses: featured-listing, listing (free listings), tags (listing labels/categories), blogs, news, events, jobs, pricing (plans), and deals, plus an "Account & Actions" section for auth-related labels. If you ever need to mirror this URL structure in Next.js or proxy/redirect from your own routes, this is the canonical slug list.
AI Agents
The AI Agents section (Getting Started, Voice AI, Conversation AI, Knowledge Base, Agent Templates, Content AI, Agent Logs) is present in the sidebar but every sub-tab rendered completely empty in this account — no agents have been created yet. I can't tell you how a configured agent behaves until one exists; if AI-driven chat/voice agents are part of your plan, you'd need to build one first (there's a "Build using AI" option I saw elsewhere in the Automation builder that may extend to agents too) and then re-audit this section.
A few things I deliberately did not do: I didn't generate the AI Conversations API key or add/save any workflow trigger, since both would alter your account's live configuration — you should decide those steps yourself. I also noticed the Settings > Custom Code tab exists (for injecting site-wide scripts) but I could not get it to render in this session after repeated attempts; it may be worth checking directly, since custom code injection is often the simplest bridge for embedding a Next.js widget or postMessage bridge into the SmartDirectoryAI site.
What this means for your Next.js integration
Practically, you have three realistic integration paths. First, keep SmartDirectoryAI as the public directory (on your white-labeled domain) and build your Next.js project as a separate marketing/utility site, linking between them — lowest effort, no API needed. Second, use SmartDirectoryAI's own extensibility: embed HighLevel forms into your Next.js pages, and use the Workflow Mapping + Inbound Webhook pattern to push directory events into your own systems (or the reverse: your Next.js app posts into those same webhook URLs to trigger HighLevel automations). Third, go fully headless: generate the AI Conversations API key, get formal API documentation from SmartDirectoryAI/HighLevel, and pull listing, category, and claim data into a custom Next.js frontend while SmartDirectoryAI stays the backend of record for listings, plans, and payments (via Stripe). Given what I found — a real feature-gated pricing engine, a working webhook-triggerable automation layer, and a documented (if not fully exposed) API key mechanism — option two or three are both feasible, but you'd want the vendor's API docs before committing engineering time to the headless approach.
